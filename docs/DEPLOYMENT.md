# 部署指南

MixOS 的部署包括 Linux 服务、ESP32-S3 应用、字体和 STM32 键盘固件。各部分的构建、写入和运行检查彼此独立，成功上传文件不等于设备已运行新版本。

## 部署前准备

1. 核对板卡版本、芯片、供电、USB 路由、设备身份和实际分区布局。
2. 按[构建指南](BUILD.md)生成与当前源码、工具链和配置一致的产物；保留原始构建报告。
3. 运行[离线测试](TESTING.md)，确认当前环境实际执行了哪些用例、哪些被跳过。
4. 为需要写入的设备保存可用的恢复备份，准备明确的恢复方式与稳定电源。
5. 由操作员单独批准目标设备和写入范围；默认检查或打包操作不等于刷写授权。

主机通过内部 USB Hub 连接 ESP32-S3 和键盘时，应保持内部 Host 路由。切换 USB Gadget、重置 Hub 或重启 Linux 都不能直接当作 ESP32 的硬件复位或断电。

## Linux 服务

`linux/mixosd.service` 和 `linux/99-mixos.rules.example` 是模板，需填写普通用户、串口组、安装路径与精确设备标识。`typixdeck` 命名的配置属于板卡示例，不能直接套用到身份不同的设备。

- 以普通用户运行 `mixosd`，终端继承该用户权限，不提供 root 自动登录。
- 将串口权限限制到明确设备，避免对所有串口授予全局写权限。
- 更新工具需要维护锁、受控的服务停止／恢复权限，以及可持续运行的 systemd 用户任务。
- 服务和运行器安装位置应稳定；发布入口引用的文件不能随构建清理而删除。

详细配置见 [Linux 主机服务](linux.md)；应用、模型和语音依赖见 [应用与 AI 后端](AI_DECK.md)。

## ESP32 日常更新

已运行兼容接收端且具有正确 A/B 布局的设备，使用 `tools/mixos_esp_update.py` 或已安装的 `mixos-esp-update`。

先做本地检查：

```sh
python3 tools/mixos_esp_update.py inspect --package /path/to/release
python3 tools/mixos_esp_update.py apply --package /path/to/release --dry-run
```

实际操作前核对设备与权限，再明确提交更新：

```sh
mixos-esp-update apply --package /path/to/release --device /dev/serial/by-id/DEVICE_ID --timeout 60 --health-timeout 180 --wait
```

更新任务负责独占设备、记录原服务状态、传输到非运行槽、确认新启动、验证健康和恢复服务。日常流程不进入 ROM，也不要求屏幕确认或按 BOOT。

完整使用方式与成功条件见 [ESP32 日常更新](ESP_OTA.md)。

## 首次安装与恢复

不具备兼容接收端的设备不能直接套用日常 A/B 更新。首次安全安装、历史单槽布局迁移和故障恢复是不同操作，均需独立核实目标及写入区域。

首次安装工具以完整身份、已有布局、受保护应用、备份和读回证据为前提。旧接收端不安全时，应使用经过审阅的独立 ROM 流程，而不是盲目重发旧更新。写入成功、退出 ROM、启动和运行健康也必须分别判断。

见 [A/B 实现](ESP_OTA_V2.md)和 [ESP32 恢复](ESP32_RECOVERY_FLASH.md)。

## 字体与键盘

- 字体独立于应用分区。生成字体需检查字符覆盖、文件长度、授权和目标分区，不能通过截断文件适配容量；见 [字体构建](FONT_BUILD.md)。
- STM32 键盘有独立芯片、ROM 身份和恢复路径。键盘刷写不得误选 ESP32，也不能把 DFU 离开成功当作按键可用；见 [键盘刷写](KEYBOARD_FLASH.md)。
- 普通 ESP32 应用更新不应顺带刷写 bootloader、分区表、字体、键盘或清空 NVS。

## 异常处理与运行记录

每次部署在本地保存构建来源、目标摘要、任务 ID、原服务状态和结果。需要 ROM 写入时，另外保存写前备份、实际允许变化范围和完整读回。

出现超时、失联或状态未知时，先查询同一任务与事务。通信恢复不意味着需要再次传输镜像；新建目录或任务 ID 也不代表旧写入已经安全结束。失败记录与后续对账记录应分别保留。

应用标记为 VALID 后的运行故障不一定自动换槽。软件看门狗能覆盖的故障、实体显示、USB 连通性、回滚和断电行为需要各自验证。完全失去响应的恢复需要独立 EN／BOOT 控制或人工介入；高风险测试应使用备用板或已具备独立恢复通道的设备。
