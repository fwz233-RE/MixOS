# 键盘实现

STM32 键盘固件基于固定版本 QMK，负责物理矩阵扫描与 I²C 事件传输；ESP32-S3 负责将事件转换成终端文本和本地设备动作。线协议见 [KEYBOARD_V1](../protocol/KEYBOARD_V1.md)。

## 模块

- `firmware/keyboard/`：矩阵、事件 FIFO、I²C 从机和本地恢复按键。
- `firmware/esp32s3/main/mix_input.c`：不依赖 ESP-IDF 或 QMK 的 C11 按键解释层。
- `firmware/esp32s3/main/mix_keyboard.c`：共享 I²C 总线上的主机驱动和恢复同步。

输入回调提供明确长度的字节或本地动作。Ctrl+Space 等可能产生 NUL，调用方必须按长度处理并立即消费或复制缓冲区。

驱动在主任务中周期调用，不在中断或 USB 回调中运行。初始化使用已有共享总线，不重新安装总线或改写传感器配置。各次调用限制 I²C 工作量，离线时降低轮询频率。

## 按键语义

矩阵行列以零为起点，完整映射以 `mix_input.c` 为准：

- 五个空格触点作为同一个逻辑空格键，分别追踪物理按下状态。
- Fn、Sym、Ctrl、Alt 和左右 Shift 是按住生效，不是锁定层；Fn 优先于 Sym。
- 数字区和部分字母结合 Fn 提供 F1–F12，方向区结合 Fn 提供导航键。
- Sym 提供标点，Shift 对字母与美式标点生效；Ctrl 产生控制字符，Alt 可添加 Escape 前缀。
- 导航和功能键输出带修饰参数的终端转义序列。
- 六个实体键从左到右为锁屏、音量减、音量加、亮度减、亮度加、键盘背光；这些本地动作不作为普通文本重复发送。原 HOME 动作名保留兼容别名，但实体键现在用于锁屏，回首页使用底部 Home 触控目标。

重复键使用回绕安全的毫秒计时，首次等待后按固定间隔重复；最新可重复按键优先，释放后不恢复更早仍按住的键。

## 断连恢复

链路失联、队列溢出、版本不兼容、CRC／序列／矩阵错误都会进入等待释放状态。此时继续排空事件但不向应用发键，只有确认完整的全释放边界后才恢复。

驱动和解释层分别处理同步与按住状态，避免断连后重放修饰键或产生重复字符。回调触发输入重置时，同一批剩余事件也必须停止分发。

## USB 与本地救援

MixOS 键盘禁止正常物理按键直接发送 USB 输入报告，终端输入走 ESP32 的 I²C 路径。QMK 仍可能枚举 HID 接口，抑制输入报告不等于删除 USB 描述符。

本地恢复独立于 Linux 与 ESP32：

- 上电时按住 Tab（R2C0）进入 Bootmagic 路径。
- 按住 Fn（R3C0）＋菱形键（R0C9），或 Sym（R5C0）＋菱形键三秒，且不按其他实际按键，请求本地救援。

这些行为依赖实际安装的键盘固件。无法进入 ROM 时不能假设远程输入能替代物理矩阵，也不应擅自切换 BOOT0 或共享供电。

## 构建与测试

QMK 固定版本与目标要求见 `firmware/keyboard/QMK_PIN.json`、[构建指南](BUILD.md)和[来源说明](SOURCES.md)。新增 QMK 功能或更换 keymap 后，需要重新核对物理输入隔离。

```sh
python3 -m unittest discover -s tests -p 'test_keyboard*.py' -v
python3 firmware/keyboard/tools/verify_qmk.py
```

上游校验器会访问固定的公开源码；主机测试覆盖真实 C 输入层、传输层、ESP 驱动和 STM32 钩子，依赖 C 编译器或可用 WSL。

测试桩不能证明矩阵电气行为、真实 I²C 寄存器副作用、USB 报告抑制、SRAM 余量或救援按键可用。实际安装前还需目标 ELF／map 检查和独立设备验证；刷写条件见 [键盘部署](KEYBOARD_FLASH.md)。
