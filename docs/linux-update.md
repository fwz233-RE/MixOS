# Linux 更新工具选型

仓库中保留了不同用途的更新与恢复工具。选择工具时，应先区分日常应用更新、受限维护握手、首次安装和 ROM 恢复。

## 日常 A/B 更新

兼容接收端使用 `tools/mixos_esp_update.py`，安装后的命令为 `mixos-esp-update`。它负责发布包检查、维护锁、systemd 任务、精确运行身份和服务恢复；`tools/deploy_ota.py` 是可选 SSH 包装器。

它不是 Linux 系统升级器，也不自动修改 ESP32 的分区布局。使用方法见 [ESP32 日常更新](ESP_OTA.md)。

## 旧版离线预检与维护工具

`tools/update_esp.py` 保留旧工厂布局的镜像预检和受限维护流程。它不是当前 A/B 发布包入口；新 A/B 分区表不应拿来满足其旧布局检查。

该工具默认检查镜像 SHA、ESP 格式、芯片与段边界，不访问设备。自动 Flash 写入路径会明确拒绝；不能把它的拒绝理解为所有 MixOS 更新工具都不支持刷写。

`--execute --maintenance-only` 属于明确的 ROM 维护操作，要求指定身份、已停服务和独立记录，并保留旧工具自己的交互条件。具体参数以 `python3 tools/update_esp.py --help` 为准，不应把该旧流程当作日常免按键 A/B 更新。

## 首次安装与恢复

`tools/bootstrap_ota_on_pi.py` 及配套工具用于独立审批的安全接收端首次安装。审批绑定构建来源、目标与允许变化范围，不因日常更新失联而自动获得授权。

其他部署／恢复工具可能固定了特定板卡、布局或历史基线。运行前必须核实源码配置和目标状态，不可将通用命令行参数当作已完成硬件适配。

## 共同边界

- 能力查询无响应只表示状态未知，不能据此认定设备是旧固件或需要迁移。
- USB 标识与 CRC 提供一致性检查，不是密码学设备认证。
- 普通终端内容不能授予维护权限。
- 更新结果未知时先检查已有事务，不自动换工具、重刷或进入 ROM。
- 日常更新、ROM 写入及硬件复位需分别核实前提；详见 [部署指南](DEPLOYMENT.md)与 [恢复说明](ESP32_RECOVERY_FLASH.md)。
