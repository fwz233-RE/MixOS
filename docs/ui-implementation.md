# 界面实现与集成

ESP32-S3 使用 `mix_ui.c` 绘制本地界面，通过 `mix_view.h` 读取设备状态，并将用户操作排队交给主循环执行。Linux 应用以终端文本呈现，不传送桌面画面。

## 页面与偏好

- 首页提供“实时翻译”“记笔记”“智能体”和“设置”四个入口；右下角卡片直接打开固定设置分页，不再进入游戏页面，也不创建游戏应用编号。
- 智能体首页卡片副标题为“编程与工具”（英文为 `Code & tools`）。四张卡片及其启动标题共同使用 70px 图标、50px 标题、33px 副标题，同一基线偏移、留白、颜色和按压位移；长文字按同一宽度省略，不单独缩小智能体字号。
- 应用页承载翻译、笔记或 Linux 终端。进入页面请求打开相应会话，离开时请求关闭已打开或正在建立的会话，不提供多应用后台会话。智能体是本地占位页，保留导航但不请求终端会话。
- 设置入口打开八项固定分页：主题、屏幕、声音与键盘、网络、电源、设备、系统和关于。设置正文不滚动、不响应上下拖动；每一页的控件都必须位于 `1024×648` 的正文区域内，主题单独占一页。
- 十二种离线、手工编写的 Material 3 风格颜色预设（石墨薄荷、纸白森林、午夜蓝、暖琥珀、海洋蓝、薰衣草、玫瑰红、琥珀金、深青绿、靛青、珊瑚橙、青柠绿）、中文／英文和终端字号保存在 NVS 的 `mixui` 命名空间，键分别为 `theme`、`lang`、`term`。原四种主题的索引不变。**这些 RGB 常量不是官方 Material Theme Builder 或 Material Color Utilities 算法生成的结果**；使用相同颜色角色名称，也不等于通过完整 Material 规范或无障碍认证。Material 3 允许由来源颜色生成方案，并不规定“总共十二种主题”。
- 终端提供大字 `64×20`（16×32 像素字符格）和紧凑 `80×27`（12×24 像素字符格）两档，默认大字。正文限于上方 648 像素；切换尺寸会清空网格和滚动历史，并通知主机调整伪终端尺寸。

电池、电源、传感器和主机状态来自实际状态模型。数据未知或校准不足时，应显示不可用，不能用模拟值代替测量。

## 启动、底部导航与调节反馈

- 产品启动直接显示首页，不进入锁屏，也不因实体锁屏键或 BOOT 按钮改变页面、背光或输入状态。`mix_ui_lock_key()` 保留为空操作兼容接口；设备进入运行态后保持唤醒。
- 锁屏功能已经从产品交互中移除；保留的旧锁屏状态接口不会改变启动页、背光或本地输入。触控通信出错时仍通过 `mix_ui_touch_cancel()` 取消当前操作，不伪造抬手；GT911 的重试和 AW9523 复位流程保持原有错误处理。
- 触控通信出错时，通过 `mix_ui_touch_cancel()` 取消当前操作，不伪造抬手；单纯没有 ready 帧仍属于正常空闲。GT911 连续三次通信／帧错误后移除设备句柄、恢复复位引脚、重新探测两个地址并初始化，失败时每五秒重试；AW9523 复位流程的任一步骤失败后仍尝试恢复 RST 高电平和 INT 输入模式。
- 底部栏范围为 `y=648..767`，前三个目标分别为返回、主页和暂未启用的菜单按钮，每个 `120×120` 像素（400 PPI 下约 48dp）。返回按当前层级逐层退出：网络密码页回到网络页，设置子页回到设置分类，设置分类回到首页；主页直接回首页；菜单按钮只显示图标，不打开设置、不派发动作。更新／维护期间保持导航互锁。
- 状态信息移到底栏；正文绘制和渐变不会改写底栏。时间下方为带主机时区偏移的 `YYYY-MM-DD` 日期；未报告时间显示占位符。Wi-Fi 图标下方为主机遥测中的无线接口**接收字节速率**，按十进制 B/s、KB/s、MB/s 等缩写显示，不是 Wi-Fi 协商速率，也不包含发送速率。无有效测量、非有限数或负值显示 `--`；合法零速率显示 `0.0B/s`。日期和网速均为 28px，且与电量分列，防止串行覆盖。
- 设置控件只接受原始按下点与抬手点位移不超过 12 像素的点击。进入正文外、超过阈值或通信取消会永久取消本次点击；重新进入不能触发旧控件。设置页没有滚动偏移、滚动条或隐藏的下方控件。
- 设置每页使用固定布局：主题为三列四行；显示、声音与键盘、网络、电源、设备、系统和关于页将全部操作放在正文内。网络页每页最多显示三条结果，上一页／下一页始终按有效页边界钳制；密码只保留在本地缓冲区，离开密码页或领取连接／忘记动作后清除。
- 设置、标题与按钮使用 `40px`（16sp），辅助文字 `33px`（13sp），数值 `50px`；与首页 `50px` 标题／`33px` 副标题使用同一密度换算。分类入口为两列四行固定卡片，不使用左侧滚动栏目。普通按钮高度为 `120px`，电源数值采用三列卡片。确认对话框仍使用旧小控件，不能据此宣称全界面无障碍合规。
- 固定分页正文按页整页重绘；普通遥测和通知按当前页面节流提交。旧的滚动像素搬移、延后提交和滚动条实现保留为兼容代码但不参与产品路径。通知仍在正文顶部显示约 5 秒，关闭通知的触摸不会穿透到被覆盖的控件。
- 主循环使用 `mix_ui_needs_fast_tick()` 处理应用启动动画和必要的 UI 提交；固定设置分页不通过拖动触发提交。上述间隔是软件调度约束，不是实机帧率承诺。
- 长网络名称、隐藏口令的圆点、诊断文本使用实际字体测宽并在 UTF-8 字符边界加省略号，不通过缩小字号来塞入；显示明文口令时测宽后只绘制能容纳的末尾字符，让最新输入可见，不另建口令副本。63 字节原始口令与完整网络名称保持不变。网络列表每页显示三条，名称与加密状态横向分列，下方提供分页。
- 音量、亮度、键盘背光使用同一短暂反馈浮层，包含对应图标、数值与进度条；连续按键更新原浮层，显示约 1.5 秒。音量/亮度仅在硬件接口成功后确认；键盘背光等待 STM32 上报目标等级（0..8），不是光强或 PWM 的实测值，超时/离线显示不可用。
- **60 秒自动关机尚未启用**。实机为 CM5，虽然网表与官方资料支持通过 PMIC_Enable 重新开机，但当前缺少免交互关机授权、可信的关机末阶段信号、电气/时序验证，以及与 AW9523 自愈逻辑一致的电源控制。现有 P0_2 继续保持高阻；不能用 USB 断连或超时作为断电依据。

## 主循环接口

接口见 [mix_ui.h](../firmware/esp32s3/main/mix_ui.h)：

1. 初始化 NVS、面板和字体后，在应用主任务调用 `mix_ui_init(panel)`，处理初始化失败。
2. 从同一任务调用 `mix_ui_tick()`、触控和本地按键接口，读取终端模型并领取动作。
3. 每次分发按键前先查询 `mix_ui_terminal_visible()`，决定交给本地界面还是远端终端。模态对话框中的确认键不能同时进入 Linux shell。
4. 用 `mix_ui_take_action()` 领取有界动作队列中的请求。连接状态、操作白名单、硬件写入和更新校验由主循环及对应模块负责。

远端文本只进入终端解析器，不能作为本地触控或键盘事件。`mix_ui_notice()` 接收固件生成的有界 UTF-8 通知，清理控制字符与非法字节，不用于授权维护动作。

维护操作和输入复位的本地对话框，与主机更新工具的协议授权是不同路径。当前主机维护授权见 [ESP_HOST_UPDATE.md](ESP_HOST_UPDATE.md)，正常 A/B 更新见 [ESP_OTA.md](ESP_OTA.md)。

Wi-Fi 口令仅在动作处理需要的短期缓冲中保留：主循环领取连接／忘记动作后，应立即读取所需数据，界面在下一次 tick 清除口令。日志与截图仍可能包含用户信息，应按敏感诊断资料处理。

## 渲染与内存

- 界面分配一块 `1024×768`、RGB565 的 PSRAM 缓冲，共 1,572,864 字节（1.5 MiB）。面板扫描缓冲另由显示驱动持有。
- 首页启动采用图标与标题向应用页位置移动的 300 毫秒过渡，使用平滑插值；初始整帧完成后才开始计时，中间帧只绘制新旧位置的合并矩形，最短软件准入间隔 16 毫秒，实际节奏受面板扫描和实机耗时限制。当前 PCLK 已回退为 26 MHz；按 1144×803 总时序计算，理论扫描率约 28.3 Hz，并非实测动画帧率。
- 2026-09-21 的 53 MHz 实验通过了应用更新健康检查，但用户实测报告整屏抖动、花屏和触控无响应，已撤回该配置并刷入保留字体增强的 26 MHz 版本。历史发布包 `terminal-contrast-pclk53-20260921` 不可作为稳定版本再次部署；协议心跳、首帧提交和帧缓冲截图均不能证明物理扫描正确。高 PCLK 引起的带宽／时序问题仍需独立测量，不能将理论扫描率写作已验证的 60 Hz。
- `mix_present.c` 获取驱动的两个扫描缓冲，将局部改动复制到空闲缓冲，提交驱动缓冲地址，并等待后续 `on_frame_buf_complete`。普通调用随即同步旧缓冲；终端局部更新可延后同步，记录最多八个待补齐矩形，下次换帧前合并处理，不保留调用者画布指针、不新增整屏内存。任何时刻都不写扫描中的缓冲。依赖 ESP-IDF 5.4.2 的 RGB bounce-buffer 回调语义；超时或驱动错误锁定后续写入，交给现有健康检查处理，不能猜测缓冲所有权。
- 启动请求立即发出，不等待动画。图标移动结束且应用首屏可用后，先用约 100 毫秒淡出到主题背景，再将一次渲染的应用首屏用约 175 毫秒淡入；Agent 沿用该交接，最终只留下空白正文。首页第四卡直接打开设置，不播放应用启动动画。状态栏不参与渐变。
- 等待应用时保留图标与标题，并使用不表示完成比例的三点呼吸提示，仅刷新 32 像素高的条带；`OPENED` 不等于首屏已经绘制，优先等待终端实际内容，已打开但刻意空白的会话最多等待 750 毫秒。内容就绪后等待页也通过淡出—淡入交接，Linux 断连立即更新提示。
- 渐变仅处理每行首末非背景像素之间的范围，用 RGB565 三通道查表插值，额外固定存储小于 8 KiB。淡出末帧已使两个驱动缓冲的应用区域等于背景，淡入前直接复用 UI 画布绘制目标，因此两段渐变之间不新增整屏复制。
- 渐变期间 UI 画布保持不变，终端模型继续收取输出并记录脏行；淡入结束后更新这些行，避免目标图像被中途改写。过渡及等待期间不转发终端按键或穿透触控，Home／Escape 可中断。维护忙、更新状态、会话失效或绘制错误会释放渐变引用并按现有刷新和健康检查处理。
- 动画复用现有画布和驱动缓冲，不新增整屏分配，不改变 A/B 更新流程。显示提交仍采用安全双缓冲及有界帧完成等待。
- 页面、主题、语言和对话框变化触发整帧绘制；触控卡片和终端变化尽量局部刷新。
- 普通遥测快照通常每秒更新一次；终端按 16 毫秒最短提交间隔检查脏行，无变化时不提交、不推迟下次更新。连续输出后 100 毫秒内主循环用 2 毫秒检查间隔，空闲后恢复 20 毫秒，实际提交仍由同步换帧等待限速。这个软件间隔不表示 60 Hz 扫描。
- 终端将连续脏行组成局部矩形，最多六段正文，另为底栏和新变化的提示卡各预留一段；超出时只扩展最后一段正文，避免描述符越界。正文、底栏与提示卡一次提交、一次等待；沿用显示层的延后镜像同步路径，连续更新同一区域时省掉一次立即拷贝。光标旧位置、新位置都重绘，提交失败保留脏行；页面切换和完整重绘先恢复双缓冲一致性，之后才进行渐变。
- 2026-09-21 稳定时序优化启用 `CONFIG_COMPILER_OPTIMIZATION_PERF=y`（`-O2`），保留断言、看门狗、PLL240M／26 MHz、PSRAM／Flash 配置及 16 行 bounce 缓冲。新的终端回归覆盖两种字符格、稀疏更新、底栏合批、矩形超限、光标擦除、提示卡、时钟回绕、空闲检查、失败脏行保留和渐变交接；所有 UI 主机运行场景也使用 `-O2`。主机用例和成功构建仍不能替代设备上的连续输出、拖动、花屏与触控验收。
- 显示仅保留 `1024×768`、RGB565 双缓冲、26 MHz 像素时钟和 16 行 bounce 缓冲的稳定路径。高刷配置、bounce-only／RGB332 实验后端及其专用测试、构建覆盖配置和扫描统计接口已删除，不再作为默认关闭的候选留存；稳定路径的帧完成等待、渐变、延后脏区补齐、等待回调和健康计数仍保留，CPU、PSRAM 和看门狗配置不变。
- 字体通过固定字符格绘制，支持中文宽字符、终端颜色与光标；字体不可用时仅保留简化 ASCII 诊断显示。
- 电量历史读取已有 RAM 采样，界面不自行采样，也不凭历史曲线推断未校准容量。

`mix_ui_draw_healthy()` 检查完整首帧提交及后续绘制错误。主循环还要求新的 RGB 扫描回调；这些软件状态不证明实体屏幕、背光或颜色已经正确。

`mix_ui_framebuffer()` 提供只读诊断视图，不锁住绘制过程，因此截图可能撕裂。截图应保持有界开销，不能阻塞显示；它也不能替代实体屏幕观察。

`mix_ui_performance()` 提供有界 JSON 快照。首页／应用保留启动与渐变统计；设置使用 `scene=settings`，包含提交次数 `frames`、`draw_max_us`、`present_max_us`、`max_gap_ms`、提交面积 `last_pixels`、正文绘制行数 `raster_rows` 和 `fast_tick`／`draw_healthy`。固定设置页正文变化时绘制 648 行，不再记录拖动条带；旧锁屏统计不属于运行产品路径。`last_pixels` 是 UI 请求矩形面积，不是实际内存写入字节数。主机通过 `UI_PERF_REQUEST`（92，非零 session）读取 `UI_PERF_RESPONSE`（93），不打开应用、不注入输入、不授权更新。计时和驱动计数均不等同于实体屏幕帧率，离线模拟与 GIF 不能替代实机验收。

实现参考：[ESP-IDF 5.4.2 RGB 双缓冲与 bounce buffer 文档](https://docs.espressif.com/projects/esp-idf/en/v5.4.2/esp32s3/api-reference/peripherals/lcd/rgb_lcd.html)。

## 笔记可读性与应用内返回

笔记使用独立的 `48×16` 字符格，单格 `21×40` 像素、34 像素字号，比通用大字终端的 26 像素字号提高约 31%。进入笔记前更新终端解析器尺寸，应用 OPEN 请求携带此尺寸；term-ime 留出一行候选栏，笔记正文程序得到 48×15。离开时恢复用户的通用终端密度，不改写其持久偏好。

笔记明确绘制黑字浅底及粗体。第一行固定为“笔记”和文件名，第二行完整显示修改时间，第三行留白，正文从第四行开始。列表、状态和提示也使用显式浅底；提示缩短，保证在 48 列下仍完整显示保存及返回操作。

底栏返回产生独立的 `APP_BACK` 动作，主循环仅向匹配、可见且在线的应用会话转发：笔记使用 Ctrl+Q，翻译与 shell 使用 Escape。编辑器保存并退到列表；列表根部再次返回正常结束应用，翻译空闲页 Escape 同样退出，录音／生成／朗读时先中止当前操作。固件仅将匹配会话、四字节且退出码为零的 `EXIT` 记为正常退出，并据此回桌面；不会解析“按主页退出”等屏幕文本，也不把断连、错误退出、错误会话或重复报文当作正常返回。Home 仍可直接关闭会话并回桌面，设置入口位于首页第四卡，底栏菜单暂不执行动作。第三方 shell 内程序仍按自身 Escape 语义处理。

物理 Shift+Space 产生一次本地 IME 动作；只有可见笔记会话会收到 CSI `32;2u`。term-ime 消费此序列并切换中英文，未安装输入法时 Python 终端工具包消费该命名键，不插入多余空格。Wi-Fi 口令、桌面和 shell 不接收此快捷键序列。补丁记录于 `tools/stage_ime.py`，重新生成源码包不会丢失；普通外部终端保留上游快捷键提示。

## 2026-09-22 用户实机反馈后的修正（历史记录）

用户确认当时的 RGB332 候选没有花屏或触控失灵，但报告整体色彩异常、底部分隔线不清晰。因此当时后续正式发布恢复 RGB565／26 MHz，并曾保留默认关闭的 RGB332 实验后端；本次源码清理已将该实验后端删除，不能把颜色退化说成尚未完善的主题。底栏边界改为 3px 的 `muted` 高对比色，不再使用接近背景的 `raised` 色。

终端 `ttf_draw_cell()` 原先按字体全局 ascent/descent 压缩垂直轮廓，水平则独立按字符格宽度适配，使中文被压扁。修正为用实际字形轮廓与共享基线选择单一比例，同时缩放横纵两轴；不改本地 UI 的 `ttf_draw_text()`。笔记格子和 34px 目标字号保持不变。

动画软件准入间隔从 35ms 降到 16ms，避免已经同步等待一次扫描后再等待近一整帧。固定设置页已取消直接拖动；终端仍保留脏区／延后镜像优化。当时性能响应曾追加 `scan_frames`（驱动帧完成回调计数）、`scan_ms`（设备单调毫秒）和 `presents`（成功提交批次），用相同启动中两次采样的差值分别计算扫描率和更新率；本次清理已删除这些实验统计字段和接口。历史采样不是物理屏幕摄影测量，也不证明 60Hz；稳定显示路径的健康计数不受此次删除影响。

实时翻译改为有界短语队列，模型流式生成、语音合成、顺序播放分别执行；第一段可在整段翻译完成前开始合成／播放。每次任务拥有独立取消事件和语言快照；上一段真正播放结束后才播放下一段，返回／退出取消剩余声音。完整 WAV 接口仍有首段合成耗时，不是逐字零延迟语音流。
