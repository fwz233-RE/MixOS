# 界面实现与集成

ESP32-S3 使用 `mix_ui.c` 绘制本地界面，通过 `mix_view.h` 读取设备状态，并将用户操作排队交给主循环执行。Linux 应用以终端文本呈现，不传送桌面画面。

## 页面与偏好

- 首页提供翻译、笔记、Agent 和设置四个入口；Agent 目前仅为占位页，不创建终端会话。
- 应用页承载翻译、笔记或 Linux 终端。进入页面请求打开相应会话，离开已打开会话的应用页请求关闭它，不提供多应用后台会话。
- 设置分为外观、网络、电源、设备、系统五组；普通 Linux 终端入口位于系统组。
- 四种主题、中文／英文和终端字号保存在 NVS 的 `mixui` 命名空间，键分别为 `theme`、`lang`、`term`。
- 终端提供大字 `64×22`（16×32 像素字符格）和紧凑 `80×28`（12×24 像素字符格）两档，默认大字。切换尺寸会清空网格和滚动历史，并通知主机调整伪终端尺寸。

电池、电源、传感器和主机状态来自实际状态模型。数据未知或校准不足时，应显示不可用，不能用模拟值代替测量。

## 主循环接口

接口见 [mix_ui.h](../firmware/esp32s3/main/mix_ui.h)：

1. 初始化 NVS、面板和字体后，在应用主任务调用 `mix_ui_init(panel)`，处理初始化失败。
2. 从同一任务调用 `mix_ui_tick()`、触控和本地按键接口，读取终端模型并领取动作。
3. 每次分发按键前先查询 `mix_ui_terminal_visible()`，决定交给本地界面还是远端终端。模态对话框中的确认键不能同时进入 Linux shell。
4. 用 `mix_ui_take_action()` 领取有界动作队列中的请求。连接状态、操作白名单、硬件写入和更新校验由主循环及对应模块负责。

远端文本只进入终端解析器，不能作为本地触控或键盘事件。`mix_ui_notice()` 接收固件生成的有界 UTF-8 通知，清理控制字符与非法字节，不用于授权维护动作。

维护操作和输入复位的本地对话框，与主机更新工具的协议授权是不同路径。当前主机维护授权见 [ESP_HOST_UPDATE.md](ESP_HOST_UPDATE.md)，正常 A/B 更新见 [ESP_OTA.md](ESP_OTA.md)。

Wi-Fi 口令仅在动作处理需要的短期缓冲中保留：主循环领取连接／忘记动作后，应立即读取所需数据，界面在下一次 tick 清除口令。日志与截图仍可能包含用户信息，应按敏感诊断资料处理。

## 渲染与内存

- 界面分配一块 `1024×768`、RGB565 的 PSRAM 缓冲，共 1,572,864 字节（1.5 MiB）。面板扫描缓冲另由显示驱动持有。
- 页面、主题、语言和对话框变化触发整帧绘制；触控卡片和终端变化尽量局部刷新。
- 普通遥测快照通常每秒更新一次；终端每 50 毫秒检查脏行，合并相邻行后按全宽条带提交。该周期不是屏幕刷新率保证。
- 字体通过固定字符格绘制，支持中文宽字符、终端颜色与光标；字体不可用时仅保留简化 ASCII 诊断显示。
- 电量历史读取已有 RAM 采样，界面不自行采样，也不凭历史曲线推断未校准容量。

`mix_ui_draw_healthy()` 检查完整首帧提交及后续绘制错误。主循环还要求新的 RGB 扫描回调；这些软件状态不证明实体屏幕、背光或颜色已经正确。

`mix_ui_framebuffer()` 提供只读诊断视图，不锁住绘制过程，因此截图可能撕裂。截图应保持有界开销，不能阻塞显示；它也不能替代实体屏幕观察。

## 离线预览

直接打开 [tools/preview/index.html](../tools/preview/index.html)，无需服务器、依赖安装或联网。数据和操作均为模拟，不连接设备或执行维护命令。

预览是独立实现，保留 Home／Power／Terminal／Device／Settings 的演示布局，与当前固件的应用首页和分组设置并非逐项一致。它适合检查主题、排版和交互原则，不应作为当前固件功能或硬件状态的证明。

## 开发检查

从仓库根目录运行：

```sh
node tests/test_preview.cjs
python -m unittest discover -s tests -p test_preview_ui.py -v
```

Node 检查预览脚本的交互契约；Python 用例在具备相应编译器时检查固件 UI 的语法、内存、渲染与输入隔离。它们不能替代真实浏览器排版、字体覆盖、LCD 时序、PSRAM、触控映射和 USB 的硬件检查。更多入口见 [测试指南](TESTING.md)。
