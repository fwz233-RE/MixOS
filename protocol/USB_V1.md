# MixOS USB protocol v1 — implementation contract

Transport: existing CDC ACM interface, raw binary, no legacy magic-string parser. USB audio remains unchanged. Integers little-endian. Each packet is COBS(encoded bytes) followed by 0x00. Decoded bytes: version:u8=1, channel:u8, type:u8, flags:u8=0, epoch:u32, session:u32, sequence:u32, payload_length:u16, payload[0..512], crc32:u32. Header 18 bytes; CRC is standard zlib CRC32 over header+payload. Maximum decoded 534 bytes; encoded buffers 540 bytes. Oversized packets discarded through next delimiter. Unknown/invalid flags/version/CRC/length rejected. CRC is not authentication; physical USB and Linux serial permissions form trust boundary.

Channels: CONTROL=0 TERMINAL=1 STATUS=2 JOB=3 MAINTENANCE=4 LOG=5 NET=6.
Types: HELLO=1 HELLO_ACK=2 PING=3 PONG=4 ERROR=5 CREDIT=6 OPEN=16 OPENED=17 DATA=18 INPUT=19 RESIZE=20 CLOSE=21 EXIT=22 STATUS_REQUEST=32 STATUS=33 JOB_START=48 JOB_PROGRESS=49 JOB_CANCEL=50 JOB_RESULT=51 PREPARE_UPDATE=64 UPDATE_READY=65 ENTER_BOOT=66 OTA_BEGIN=67 OTA_READY=68 OTA_DATA=69 OTA_ACK=70 OTA_END=71 OTA_DONE=72 OTA_ABORT=73 OTA_STATUS=74 OTA_IDENTIFY=75 OTA_IDENTITY=76 CAPS_QUERY=77 CAPS=78 OTA_REQUEST=79 LOG=80 OTA_RESPONSE=81 NET_SCAN=96 NET_LIST=97 NET_CONNECT=98 NET_FORGET=99 NET_RESULT=100.

ESP initiates HELLO periodically until acknowledged, with a fresh nonzero epoch per connection attempt cycle (not per retry). Payload <HH>: maximum payload=512, terminal receive window=4096. HELLO and HELLO_ACK have channel 0 session 0. Host replies HELLO_ACK same payload, same epoch. All other frames must match established epoch. Each sender increments its uint32 sequence; duplicates/stale frames discarded using modular comparison. Retries of HELLO are idempotent; a changed epoch closes PTY, cancels jobs, and drops pending data. PING/PONG empty, session 0, every 2 seconds; timeout 8 seconds clears link. Connection loss resets input; no stale keystroke replay.

Terminal OPEN: channel1 session nonzero chosen by ESP, payload `<HH>` columns, rows, optionally followed by `length:u8` and that many UTF-8 bytes naming the application to start. A four-byte payload is the original geometry-only request and still means the plain shell. The name must be exactly one of `shell`, `translate`, `notes`, `agent`; the host maps it through a fixed table to an absolute program and its fixed arguments. **No command string, path, argument or environment value ever crosses this link.** An unknown or malformed name is an ERROR and starts nothing. Host only accepts one session, returns OPENED echoing the four geometry bytes after creating an unprivileged PTY. Geometry is chosen by the device and may change between sessions; v1 devices use 80x28 or 64x22. ERROR: UTF-8 bounded reason, same request session. Terminal DATA host→ESP and INPUT ESP→host: raw terminal bytes, <=512. DATA can split UTF-8/ANSI anywhere. RESIZE `<HH>`. CLOSE empty. EXIT `<i>` process exit code, followed by cleanup. Initial prototype closes session on USB loss; no reattach or output replay.

The ESP answers a cursor-position report (`CSI 6 n`) and a primary device-attributes query (`CSI c`) as ordinary INPUT on the same session. Without those answers an application that probes the terminal at startup waits forever. Secondary and tertiary attribute queries are deliberately unanswered. The terminal renderer implements the alternate screen, insert/delete line and character, erase character, scroll regions, 256-colour and direct-colour SGR; it implements no mouse reporting, so a stream can change what is displayed but never what the device does. `linux/mixos.terminfo` claims exactly these capabilities and nothing more.

CREDIT channel1 session active, <I> absolute cumulative number of DATA payload bytes the ESP permits host to send in this session (modulo uint32). On OPENED ESP grants 4096; once consumed by parser it increases grant by consumed byte count. Host tracks sent total and never sends beyond grant; pause PTY reads when no credit or TX queue full. Control frames not charged. Only DATA uses credit. INPUT is bounded by local/host queues; overflow must signal/close, never silently discard or duplicate commands. CREDIT is consumed by session and is idempotent, not additive. Sender uses modular arithmetic limited to <=4096 window.

STATUS_REQUEST empty. STATUS channel2/session0: bounded UTF-8 JSON `{"uptime_s":number,"cpu_pct":number,"mem_used_kib":number,"mem_total_kib":number,"temp_c":number|null,"time_s":number,"tz_offset_min":number}` plus optional `"wifi":{"connected":bool,"ssid":string,"signal":number|null}` and `"ip":string`. Unknown metrics null; not zero. **An absent `wifi` object means unknown, which is not the same as disconnected**, and the device shows it as unknown rather than inventing a radio state it was never told about. `time_s` is the host's wall clock in Unix seconds; the device has no running clock of its own and carries the seconds between polls on its own monotonic counter.

Network: the device asks, the host acts through its own bounded wrapper, and **no command string crosses the channel**. NET_SCAN channel6, nonzero session chosen by the device, empty payload. The host answers NET_LIST on the same session with a packed list: `count:u8` then per entry `flags:u8` (bit0 secured, bit1 a saved profile already exists), `signal:u8` 0..100, `length:u8`, UTF-8 SSID bytes, at most 32. An entry that would not fit the 512-byte payload is dropped, never truncated: half an SSID is not a network anyone can choose. Hidden networks are omitted. NET_CONNECT and NET_FORGET carry `length:u8` SSID then optionally `length:u8` passphrase, each length-prefixed and bounded at 32 and 63 bytes. The host answers NET_RESULT with `code:u8` (0 success) followed by a bounded UTF-8 message. One request runs at a time; a second is refused immediately rather than queued, so the device never waits without being told why. Every host-side invocation is an explicit argument vector, the request reaches the helper on stdin so a passphrase never appears in the process table, and the helper runs as the ordinary service user: an authorisation failure is reported, never escalated.

Jobs: JOB_START channel3 session=nonzero job id, payload ASCII "sha256" (fixed example only); PROGRESS UTF-8 JSON {"percent":0..100}; RESULT bounded JSON; CANCEL empty. No shell interpolation for job requests. Terminal shell is the explicitly configured ordinary Linux user and carries that user's permissions.

Maintenance is explicitly host-authorized and separate from arbitrary terminal data: executing the updater sends PREPARE_UPDATE (nonzero session=request id). On an established link with the current epoch, fresh sequence and empty payload, ESP emits UPDATE_READY automatically without a screen confirmation. Updater then sends ENTER_BOOT for the same id within 15 seconds. ESP validates and consumes that one-use grant, clears inputs and restarts in ROM download mode. PREPARE alone never boots; disconnect, restart, timeout and grant expiry revoke authorization. Other requests are denied. This sequencing is not cryptographic peer authentication; trusted-host access controls remain required. No remote arbitrary flash/memory/register-write command is provided by the application protocol. Updater validates image target/layout/hash and explicit port identity, owns serial exclusively, and preserves fresh backup/full-readback safeguards; the normal service must be stopped for maintenance. The current partition layout uses A/B application slots. Application OTA uses the versioned extension in `protocol/OTA_V2.md`, preserving this framing and HELLO payload; it is separate from PREPARE/ENTER_BOOT ROM maintenance. An active receiving/committing transaction refuses ROM preparation. Rollback requires a later boot and actual health-based VALID confirmation, not merely A/B partitions. The first safety receiver installation preserves the known-good A slot through a separately authorized ROM procedure; communication silence never authorizes migration. Hardware BOOT+RESET remains a recovery option. Full-flash restore is separate from app-only upgrade. See `docs/ESP_OTA_V2.md` and `docs/ESP_HOST_UPDATE.md`.

Logs/diagnostics are framed and low priority, never unframed ASCII on CDC. Any occurrence of REBOOT_TO_BOOT_MODE in terminal text is inert. Screenshots if provided must be chunked low-priority messages; do not block control. No additional USB endpoints needed.

Testing: C and Python share deterministic golden frames, CRC failure, malformed COBS, excessive length, fragmented and concatenated packets, epoch/session resets, duplicate seq and credit, partial writes and output flood. No hardware operation is authorized by this document.
