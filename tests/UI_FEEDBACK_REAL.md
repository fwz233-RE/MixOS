# 真实生产 UI 主机截图与回归

从 MixOS 根目录在 PowerShell 执行：

```powershell
py -3.12 tests/render_ui_feedback_r6.py --strict-layout
```

默认读取现有 `build/font/MiSans-Normal-gb2312.ttf` 和 `build/host-freetype/libfreetyped.a`。Windows 通过 `tests/_support.py` 使用 WSL；机器相关覆盖参数仍为 `MIXOS_WSL_DISTRO`、`MIXOS_WSL_USER`、`MIXOS_HOST_CC`。缺少字体或 FreeType 静态库直接报错，不下载依赖、不连接设备、不构建固件。

## 输出

默认目录：`build/ui-feedback-r6-preview`。

- `home-zh.png`、`home-unlocked.png`：中文首页和上滑解锁返回。
- `lock-idle.png`、`lock-touch.png`、`lock-swipe.png`、`lock-return.png`、`lock-returned.png`、`lock-ready.png`：静止、触摸、未达阈值的上滑、回弹、完成回弹、达到解锁阈值但尚未松手。
- `settings-{appearance,network,power,device,system}-{top,bottom}.png`：五个设置分区顶部和滚动到底部。
- 每张 PNG 对应一份原始小端 `1024×768 RGB565` 文件。
- `scenes.jsonl`：逐场景主机耗时、FreeType 调用计数、实际文字位置及真实字形 alpha 边界。
- `summary.json`：汇总、输入 SHA-256、图片摘要、`scroll_regression` 连续滚动结果、检查范围和主机限制。
- `run.log`：原始主机执行输出。

`--font` 和 `--out` 可指定独立输入及输出目录。`--skip-images` 跳过 RGB565／PNG 写出，但仍执行完整布局与连续滚动检查并生成报告；它不等于跳过验证。`--no-sanitize` 可用于另行记录不带 ASan/UBSan 的主机耗时，建议使用不同 `--out`，避免覆盖有检查的结果。默认启用 AddressSanitizer、UndefinedBehaviorSanitizer、`-Wall -Wextra -Werror`。脚本名保留 `r6` 以兼容现有入口；验证当前工作区生产源码，并非固定验证历史 r6 固件。

## 真实性与限制

`ui_feedback_real_harness.c` 直接包含生产 `mix_ui.c`，链接未经改写的生产 `ttf_font.c`、`mix_terminal.c` 和现有 FreeType 库。平台替身仅提供固定示例遥测、网络列表、电池采样、NVS、面板提交和可控时钟。

PNG 编码由 Python 标准库完成：只扩展生产 RGB565 像素并压缩，没有 Pillow/fontTools 文字绘制、字体重新排版或旧预览工具的界面模拟。截图中的网络、电量等数据是测试夹具，不是设备状态；底栏构建标识 `12345678` 也是固定测试值。

主机执行时间包含生产 UI 绘制及真实 FreeType 调用，面板提交为无等待替身；不包含 RGB 总线、PSRAM 或实体 LCD 时序，也不是板上帧率。全套进程时间还包含诊断与文件写入，不能当成单帧耗时。

## 检查

- 生产 UI 只申请一个 `1,572,864` 字节帧缓冲，前后保护字节不变。截图写出只使用一行缓冲。逐帧对照另由测试桩分配参考图像和模拟面板像素存储，这些额外缓冲仅在主机测试中存在，不属于生产 UI 分配。
- 连续滚动通过实际 `mix_ui_touch()`／`mix_ui_tick()` 调用执行，覆盖五组设置 × 中英双语 × 12 主题的 120 组矩阵，包含 1px 位移、往返、方向改变、跨页大位移及内容失效；每帧分别比较优化画布、完整重绘参考图像和实际提交给模拟面板的像素。仅提交新条带、漏提交已移动像素同样会失败。
- 动态失效覆盖遥测、通知／浮层、网络状态、主题、语言等变化；正文内容失效必须优先于滚动复用。报告记录总帧数、条带绘制次数、往返和失效计数；`byte_equal` 与 `panel_equal` 均需成立。
- 面板替身支持生产普通／延后同步批量矩形 API，同一批只计一次提交，同时复制各矩形以模拟可见面板内容；延后同步的两个驱动缓冲生命周期由独立 `test_mix_present.py` 测试，此替身不重复模拟。此处无硬件等待，不用于推算实机帧率。
- 行复用拦截实际 `memcpy` 调用，检查每次都在正文内、保持字对齐、恰好一行宽且源目标互不重叠；完整逐帧对照验证上下两个方向的跨行处理顺序。若回退到帧缓冲 `memmove` 则立即失败，避免主机 libc 的速度掩盖 ESP32-S3 ROM 中的逐字节慢路径。
- 每个设置页先重建字体缓存记录冷渲染，再完整重绘 20 次，断言预热后的 FreeType 字形加载及尺寸切换均为零。
- 设置正文滚动后，通过区域哈希断言固定侧栏与底栏像素保持不变。
- 完全离屏的普通、限宽、居中和图标绘制不得产生任何字体查询、宽度计算或栅格化调用。
- 真实字形的非零 alpha 像素决定文字边界；检查水平边界和文字包围盒相交候选。
- 覆盖率至少 250 的字形像素在生产混合器中应等于准确前景色；检查最终帧缓冲是否被后续图形覆盖，并用故意破坏一个字形像素的自测验证检测有效。
- 检查 UTF-8 码点完整性及生产字形 advance 与绘制返回宽度一致性。
- 锁屏正文文字仅为 `MixOS`；未成功解锁的手势回弹后，正文像素与初始锁屏一致。

文字包围盒相交是候选问题，不代表所有交叠处均存在非零 alpha；工具不会把它宣称为逐像素碰撞证明。滚动视口上下边缘正常裁剪另记为 `viewport_cut`，不当作 UTF-8 断字。逐帧滚动等价性覆盖两种语言和 12 个主题；18 张 PNG 的文字布局诊断使用指定中文场景，两者范围不同。抗锯齿低覆盖率像素被擦除、文字与图标距离是否舒适、全部极端遥测组合仍不在本次穷尽检查范围内。

`--strict-layout` 遇到水平越界、包围盒相交、实心文字像素被覆盖或缺字时返回 1，仍保留 PNG 和报告。未加此参数时也会记录这些问题，但不因布局诊断失败而停止生成图片。若生产输入在编译/运行期间改变，返回 2 并要求重跑；其他编译、断言或 sanitizer 故障始终失败。最终 UI 修改完成后应重新执行本工具，以报告中的源文件摘要为准。
